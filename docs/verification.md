# Verification record

Prepared 2026-09-22.

- Both native C++17 programs compiled successfully with GCC on Linux x64, with
  `-Wall -Wextra -pedantic` and no compiler warnings.
- JavaScript source passed Node's syntax checks.
- 28 automated tests passed. Coverage includes basic safe/unsafe allocations,
  early returns, aliases, shadowed pointers, smart ownership, SQL propagation,
  constant queries, bound values, nested contexts, percentages, Unicode offsets,
  malformed requests, incomplete source, both exact source copies, and report
  escaping.
- Mocked VS Code lifecycle tests verify stale-result rejection, closing a file
  during a scan, live timer updates, no repeated count for unchanged versions,
  and use of the configured website URL.
- `example-report.json` and `example-report.html` were generated by the actual
  two-stage native pipeline using `examples/vulnerable.cpp`.
- The demo has four distinct findings: two memory and two SQL. Their occupied
  rows have count 1, 50% of that type, and 25% of all findings.

## Not verified in this environment

There is no Windows toolchain or graphical VS Code host here. Windows/MSVC and
MinGW build paths are provided but must be verified on the target machine.
Actual toolbar interaction and webview rendering inside VS Code have not been
exercised. A browser-based screenshot attempt was unavailable because a browser
executable was not installed; the HTML output is included for local preview.

The checks establish the documented prototype behavior. They do not establish
complete C++ syntax support, soundness, or completeness of vulnerability detection.
